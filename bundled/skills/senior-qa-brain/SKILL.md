# Senior QA Brain - 资深测试思维引擎

> 像资深测试工程师一样思考和分析，而不仅仅是生成测试用例模板

---

## 🎯 核心能力

这个skill让AI具备资深测试工程师的**思维方式**和**分析能力**：

1. **深度理解设计** - 从Figma设计稿中提取深层测试信息
2. **结构化思考** - 像人一样进行测试分析，而非机械生成
3. **主动发现风险** - 基于经验库自动识别潜在问题
4. **人工评审机制** - 先输出分析报告，确认理解后再生成用例
5. **自适应策略** - 根据不同项目类型调整测试方法
6. **UI自动化评估** - 自动判断每条用例的Playwright自动化可行性
7. **实用性优先** - 基于80/20原则，用20%精准测试发现80%风险 ⭐新增

## 🔄 完整工作流程

1. **Token预估** - 评估任务复杂度，预估消耗
2. **业务规则库读取** - 若 QA Agent instruction 指定了 `bundled/knowledge_base/业务规则库` 下的路径，必须先读取这些路径；不要自行扫描全量知识库
3. **Figma分析** - 深度分析设计稿，提取测试信息
4. **生成分析报告** - 选择快速版/详细版，输出测试分析报告，并包含“知识库依据”章节；若规则库未命中，明确写“规则库未命中”并列出待确认问题
5. **[可选] PRD Diff** - 若有需求文档，与报告做差距分析：补充缺失业务规则、标记设计与需求冲突点
6. **人工评审** - 确认AI理解正确，回答待确认问题
7. **分批生成用例** - 基于80/20原则，先生成核心用例（20-30条）
8. **自动化评估** - 每条用例自动标记Playwright自动化可行性
9. **质量评估** - 计算覆盖度，控制用例数量上限（小功能≤30条，中等≤60条，大功能≤100条）

### 3. Playwright UI自动化判断标准 🤖

每条用例**必须**标记自动化可行性，格式为：`**UI自动化**: ✅ 可自动化` 或 `❌ 不可自动化`

**重要**: 仅标记可行性，不要添加"自动化方式"详细说明。

#### 判断标准

**✅ 可自动化** - 满足所有条件：
- 纯Web UI操作 + 明确验证点
- 无第三方授权/支付/人机验证

**❌ 不可自动化** - 存在任一情况：
- 需人工判断视觉效果/主观感受
- 第三方OAuth/真实支付/人机验证

### 核心原则

1. **质量 > 数量**：30条精准用例 > 100条冗余用例
2. **分批生成**：先核心流程（20-30条）→ 补充异常场景（10-20条）
3. **实用性优先**：问自己"用户会这样做吗？"，不会就别测

## ⚡ 快速开始

### 仅 Figma（基本用法）

```
"请使用senior-qa-brain分析这个Figma设计
https://www.figma.com/design/xxx?node-id=xxx"
```

### Figma + 需求文档（推荐，用例更准确）

```
"请使用senior-qa-brain分析这个Figma设计
https://www.figma.com/design/xxx?node-id=xxx

需求文档：
[粘贴PRD内容 / 或提供Confluence链接]"
```

AI会在生成分析报告后自动执行PRD差距分析，补充缺失业务规则并标记设计与需求冲突。

执行步骤：
1. 预估Token
2. 询问报告模式（快速版/详细版）
3. 生成分析报告 → [有PRD时] 追加差距分析章节
4. 等待用户确认
5. 分批生成用例（含需求来源标记）
6. 输出Markdown文件
