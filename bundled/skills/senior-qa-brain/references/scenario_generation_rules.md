# 测试场景生成规则（实用性优先版）

> 基于80/20原则，生成精准实用的测试场景

## ⚠️ 重要提示

**遵循实用性原则**：
- ✅ 用20%精准测试，发现80%风险
- ✅ 用例数量上限：小≤30条，中≤60条，大≤100条
- ✅ 排除极端场景、第三方依赖、无法控制的内容
- ✅ 详见：`practical_test_rules.md`

## 场景生成五维模型

```
User Journey (用户旅程)
    +
Data Dimension (数据维度)
    +
State Machine (状态机)
    +
Combination (组合)
    +
Timing & Concurrency (时序与并发)
    ↓
全面的测试场景
```

---

## 维度1：基于用户旅程 (User Journey)

**核心路径**（聚焦最常用的）:
- 新用户：注册 → 首次使用 → 引导
- 老用户：登录 → 常规操作 → 退出
- 异常：网络中断 → 恢复 → 数据同步

**实用性提示**: 不测试低频路径（如API/插件等高级功能），除非是产品核心特性。

---

## 维度2：基于数据维度 (Data Dimension)

### 正常数据
每个字段取典型值即可。

### 边界数据（最小/最大/临界）

**生成策略**: 每个字段取边界值

| 字段 | 最小值 | 最大值 | 临界值 |
|------|--------|--------|--------|
| 密码长度(8-20) | 8位 | 20位 | 7位(边界-1), 21位(边界+1) |
| 年龄(1-120) | 1岁 | 120岁 | 0岁, 121岁 |
| 价格(0.01-99999) | 0.01 | 99999 | 0, 0.001, 100000 |
| 列表(0-1000) | 0条 | 1000条 | 1001条 |

### 异常数据（实用版）⭐

**生成策略**: 只测试常见异常，排除极端场景

```
字符串字段:
✅ 空字符串 ""
✅ null
✅ 全空格 "   "
❌ 不测：超长字符串(10000+字符) - 极端场景

数字字段:
✅ 0
✅ 负数 -1
❌ 不测：极大值 999999999999 - 极端场景
❌ 不测：NaN、Infinity - 除非业务相关

日期字段:
✅ null
✅ 空字符串
✅ 非法格式 "abc"
❌ 不测：未来100年 - 极端场景
❌ 不测：1970-01-01 - 除非业务相关
```

### 特殊字符数据（简化版）⭐

**SQL注入测试数据**（只测1-2个）:
```
✅ ' OR '1'='1  （基础注入）
✅ admin'--      （注释绕过，可选）

❌ 不测：20种SQL注入变体
❌ 不测：时间盲注、布尔盲注等高级技巧
```

**XSS攻击测试数据**（只测1个）:
```
✅ <script>alert('XSS')</script>  （基础XSS）

❌ 不测：编码绕过（URL编码、Base64）
❌ 不测：DOM型XSS的复杂利用
❌ 不测：多种XSS变体
```

**路径穿越测试数据**（可选）:
```
✅ ../../etc/passwd  （基础路径穿越）

❌ 不测：URL编码绕过
❌ 不测：多种路径穿越变体
```

**Unicode与Emoji**（仅业务需要时测试）:
```
✅ 基础emoji（如😀）- 仅当产品支持时测试

❌ 不测：复合emoji、零宽字符等极端场景
❌ 不测：除非产品明确需要支持
```

### 极端数据（不推荐测试）❌

**超大数据量**（通常不测试）:
```
❌ 100万条列表数据 - 极端场景，用户不会遇到
❌ 10MB的文本输入 - 前端应该有限制
❌ 10000层嵌套的JSON - 理论场景
❌ 1GB的文件上传 - 应该有文件大小限制

✅ 替代方案：只测试产品文档明确的上限
   - 如产品限制文件上传10MB，则测试10MB
   - 不测试理论极限
```

**极小数据量**（有些需要测试）:
```
✅ 空数组 [] - 常见场景
✅ 空对象 {} - 常见场景
❌ 单字符 "A" - 除非最小长度是1
❌ 0.0000001 - 极端小数，除非业务相关
```

## 维度3：基于状态机 (State Machine)

测试要点：
- ✅ 所有合法状态转换
- ✅ 典型非法转换（如跳过支付、状态回退）
- ❌ 不测试所有可能的非法转换组合

---

## 维度4：基于组合 (Combination)

**实用原则**：
- ✅ 只测高频组合（覆盖70%+用户）
- ✅ 只测高风险组合（历史Bug高发）
- ❌ 不使用正交表做全量组合优化
- ❌ 不测试所有参数的笛卡尔积

---

## 维度5：基于时序与并发 (Timing & Concurrency)

**实用场景**（简化版）:
- ✅ 操作顺序错误（如未登录直接访问）
- ✅ 验证码/Token过期
- ✅ 重复点击防抖
- ❌ 不测精确的时间窗口（如59秒vs61秒）
- ❌ 不测1000人并发压力

### 并发场景（简化版）⭐

**同一用户多设备**（简化）:
```
✅ TC001: 手机和PC同时登录，验证会话处理
✅ TC002: 双开浏览器标签页，验证会话同步

❌ 不测：手机修改资料PC实时更新 - 复杂场景
❌ 不测：复杂的数据冲突处理 - 除非是核心功能
```

**多用户并发操作**（不推荐测试）:
```
❌ 不测：100人同时抢购 - 压力测试，不是功能测试
❌ 不测：1000人同时登录 - 性能测试，不是功能测试

✅ 替代方案：只测简单的重复操作
   - 快速点击按钮5次
   - 双开标签页同时提交
```

### 快速操作测试（简化版）

**防抖测试**（简化）:
```
✅ TC021: 快速连续点击按钮5次，验证只提交1次

❌ 不测：复杂的防抖时间验证
❌ 不测：精确到毫秒的防抖逻辑
```

**节流测试**（可选）:
```
⭕ TC031: 快速滚动到底部，验证节流 - 可选

❌ 不测：精确的节流时间间隔
❌ 不测：复杂的节流逻辑验证
```

## 场景生成实战：用户登录功能

### 应用五维模型生成场景

#### 维度1：用户旅程
```
新用户: 首次登录 → 密码不记得 → 忘记密码 → 重置密码 → 登录成功
老用户: 快速登录 → 记住密码 → 自动登录
异常: 多次失败 → 账号锁定 → 申诉解锁
```

#### 维度2：数据维度
```
正常数据: test@example.com / Abc123456
边界数据: 最短密码(8位) / 最长密码(20位)
异常数据: 错误密码 / 不存在的邮箱 / SQL注入字符
特殊数据: Emoji账号 / 超长密码 / 空密码
```

#### 维度3：状态机
```
未登录 → 输入账号密码 → 验证中 → 登录成功 → 已登录
   ↓                         ↓
  取消                    验证失败
                             ↓
                        重新输入 / 忘记密码
```

#### 维度4：组合
```
设备 × 网络 × 账号状态:
- iOS + 4G + 正常账号
- Android + WiFi + 锁定账号
- PC + 弱网 + 新注册账号
```

#### 维度5：时序并发
```
时序: 登录过期 → 重新登录 → 回到原页面
并发: 多设备同时登录 → 会话同步/互踢
快速: 连续点击登录按钮 → 防抖
```

### 生成的测试用例清单（实用性优先版）⭐

```
【功能测试】10条（核心流程）
TC001: 正确账号密码登录，验证成功
TC002: 错误密码登录，验证失败提示
TC003: 不存在的账号登录，验证提示
TC004: 勾选"记住我"，下次自动填充
TC005: 忘记密码入口，验证跳转正确
...

【边界测试】5条（明显边界）
TC011: 密码输入8位（最小），验证成功
TC012: 密码输入20位（最大），验证成功
TC013: 密码输入7位，验证长度不足提示
❌ 不包括：21位、1000位等极端边界
...

【安全测试】5条（简化版）
TC016: 用户名输入 ' OR '1'='1 ，验证过滤
TC017: 使用过期Token登录，验证拦截
TC018: 修改URL中的用户ID，验证越权拦截
❌ 不包括：20种SQL注入变体
❌ 不包括：复杂的XSS绕过技巧
...

【异常测试】5条（常见异常）
TC021: 网络断开时点击登录，验证提示
TC022: 服务器500错误，验证友好提示
TC023: 登录接口响应超时，验证超时提示
❌ 不包括：所有HTTP状态码测试
...

【并发测试】3条（简化版）
TC026: 快速点击登录按钮5次，验证防抖
TC027: 双开标签页同时登录，验证会话处理
❌ 不包括：1000人并发压力测试
...

总计: 28条测试用例（符合小功能≤30条的标准）
```

## 场景生成检查清单

在生成测试场景时，确保覆盖以下方面：

### ✅ 功能完整性
- [ ] 主流程：Happy Path全覆盖
- [ ] 分支流程：所有if/else分支
- [ ] 边界条件：最小值/最大值/临界值
- [ ] 异常流程：错误处理和容错

### ✅ 用户视角
- [ ] 新用户首次使用
- [ ] 老用户常规操作
- [ ] 高级用户深度使用
- [ ] 误操作恢复

### ✅ 数据维度
- [ ] 正常数据
- [ ] 边界数据
- [ ] 异常数据
- [ ] 特殊字符
- [ ] 极端数据

### ✅ 状态转换
- [ ] 所有合法状态转换
- [ ] 所有非法状态转换
- [ ] 状态回退和恢复
- [ ] 中间状态超时

### ✅ 组合场景
- [ ] 高频组合优先测试
- [ ] 高风险组合重点测试
- [ ] 使用正交表优化

### ✅ 时序并发
- [ ] 操作顺序依赖
- [ ] 时间窗口限制
- [ ] 多设备并发
- [ ] 快速操作防抖

### ✅ 安全性
- [ ] 注入攻击（SQL/XSS/CSRF）
- [ ] 权限校验（越权访问）
- [ ] 加密传输（HTTPS/Token）
- [ ] 频率限制（防刷）

## 总结：场景生成的黄金法则（实用性优先版）⭐

1. **80/20原则** - 用20%精准测试，发现80%风险
2. **质量优于数量** - 30个高质量场景 > 100个冗余场景
3. **真实场景优先** - 用户真实使用场景 > 理论边界场景
4. **排除不可控内容** - 不测第三方依赖、极端场景
5. **简化边界和安全测试** - 典型场景足够，不追求完美
6. **控制用例数量** - 小≤30条，中≤60条，大≤100条

**记住**: 好的测试场景来自**实用性思考**，问自己"用户会这样做吗？"
