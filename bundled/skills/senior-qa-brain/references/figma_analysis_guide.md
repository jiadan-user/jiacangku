## 第1层：结构分析

### 1.1 页面组织结构

#### 通过Figma API获取
```javascript
// 使用 get_design_context 或 get_metadata
{
  pages: [
    {name: "登录页", id: "0:1"},
    {name: "注册页", id: "0:2"},
    {name: "首页", id: "0:3"}
  ]
}
```

#### 分析要点

| 分析项 | 提取信息 | 测试启示 |
|--------|---------|---------|
| 页面数量 | 总共多少个页面 | 需要测试的页面范围 |
| 页面命名 | 功能模块分类 | 测试用例分组依据 |
| 页面关系 | 父子/平级关系 | 导航测试路径 |
| 页面状态 | 同一页面的不同状态 | 状态切换测试场景 |

#### 示例分析

```
检测到Figma结构:
├─ 登录注册模块 (3个页面)
│  ├─ 登录页
│  ├─ 注册页
│  └─ 忘记密码页
├─ 主功能模块 (5个页面)
│  ├─ 首页
│  ├─ 列表页
│  ├─ 详情页
│  ├─ 编辑页
│  └─ 设置页
└─ 状态页面 (3个页面)
   ├─ Loading状态
   ├─ Empty状态
   └─ Error状态

→ 测试启示:
  - 需要测试 3+5+3 = 11个页面
  - 需要测试页面间的跳转路径（至少15条路径）
  - 需要测试每个页面的3种状态（Loading/Empty/Error）
```

### 1.2 组件依赖关系

#### 识别方法
- 查看组件实例化关系
- 识别共用组件
- 分析组件变体（variants）

#### 测试启示

```
示例：检测到"Button"组件有4个变体
- Primary Button (主按钮)
- Secondary Button (次按钮)
- Disabled Button (禁用状态)
- Loading Button (加载状态)

→ 测试用例:
  TC001: 验证Primary Button的点击响应
  TC002: 验证Disabled Button不可点击
  TC003: 验证Loading Button禁止重复点击
  TC004: 验证不同按钮的视觉一致性
```

## 第2层：交互分析

### 2.1 表单元素识别

#### 识别清单

| 元素类型 | Figma特征 | 需要提取的信息 | 测试重点 |
|---------|-----------|---------------|---------|
| 文本输入框 | Input/TextField组件 | 标签、占位符、必填标记 | 格式校验、长度限制 |
| 密码输入框 | 带遮罩的Input | 显示/隐藏密码按钮 | 特殊字符、强度校验 |
| 下拉选择 | Select/Dropdown | 选项列表、默认值 | 选项完整性、搜索 |
| 单选框 | Radio Button | 互斥选项、默认选中 | 互斥性、必选校验 |
| 复选框 | Checkbox | 可多选项、默认状态 | 全选、反选、依赖 |
| 日期选择器 | DatePicker | 日期范围、格式 | 边界日期、时区 |
| 文件上传 | Upload按钮 | 文件类型、大小提示 | 类型校验、大小限制 |
| 开关 | Toggle/Switch | 开关状态 | 状态切换、持久化 |

#### 深度分析：文本输入框

```
Figma设计显示:
┌─────────────────────────────────┐
│ 邮箱地址 *                       │
│ ┌─────────────────────────────┐ │
│ │ 请输入邮箱地址               │ │
│ └─────────────────────────────┘ │
│ 💡 将用于接收验证邮件           │
└─────────────────────────────────┘

从中提取:
✓ 字段名: "邮箱地址"
✓ 必填: * 标记
✓ 占位符: "请输入邮箱地址"
✓ 帮助文本: "将用于接收验证邮件"

推断测试场景:
1. 必填校验: 不输入邮箱，验证是否提示
2. 格式校验: 输入非邮箱格式，验证是否提示
3. 边界测试: 超长邮箱地址（>255字符）
4. 特殊字符: 邮箱包含中文/空格/特殊符号
5. 唯一性: 邮箱已被注册的情况
6. 业务逻辑: 验证邮件是否真的发送到该邮箱
```

### 2.2 状态切换识别

#### 常见状态类型

| 状态类型 | Figma命名模式 | 识别方法 | 测试场景 |
|---------|--------------|---------|---------|
| 默认状态 | Default / Normal | 基础页面 | 初始加载 |
| 悬停状态 | Hover | 鼠标悬停效果 | 鼠标交互 |
| 激活状态 | Active / Focus | 聚焦/选中状态 | 键盘导航 |
| 禁用状态 | Disabled | 灰色/不可点击 | 条件不满足 |
| 加载状态 | Loading | 骨架屏/转圈 | 异步请求中 |
| 成功状态 | Success | 绿色提示 | 操作成功 |
| 错误状态 | Error / Failed | 红色提示 | 操作失败 |
| 空状态 | Empty | 无数据占位 | 首次使用 |

#### 状态机推导

```
示例：按钮状态机

    [初始] Default
       ↓ (鼠标移入)
    Hover
       ↓ (点击)
    Active → Loading
       ↓ (请求完成)
    ├─ Success (成功)
    └─ Error (失败)
       ↓ (3秒后)
    Default (恢复)

测试用例:
TC001: 点击按钮后，验证进入Loading状态
TC002: Loading状态下，验证按钮不可再次点击
TC003: 成功后，验证显示Success状态并恢复
TC004: 失败后，验证显示Error提示信息
TC005: 快速连续点击，验证防抖机制
```

### 2.3 动效与反馈

#### 从Figma提取

| 动效类型 | Figma标注 | 需要提取 | 测试验证 |
|---------|----------|---------|---------|
| 页面过渡 | Transition动画 | 时长、类型 | 流畅度、时长准确性 |
| 弹窗动画 | Modal进入/退出 | 动画方向、遮罩 | 动画完整性、遮罩点击 |
| Toast提示 | 消息提示 | 位置、时长 | 显示位置、自动消失 |
| 加载动画 | Spinner/Skeleton | 类型、位置 | 何时显示、何时消失 |
| 下拉刷新 | Pull to refresh | 触发距离 | 触发阈值、加载状态 |

## 第4层：边界推断

### 4.1 视觉边界

#### 布局边界测试

```
从Figma设计推断:

固定宽度设计 → 需要测试窗口缩放
响应式设计 → 需要测试断点（768px, 1024px, 1920px）
弹性布局 → 需要测试内容溢出
```

#### 常见视觉边界场景

| 边界类型 | 测试场景 | 验证点 |
|---------|---------|--------|
| 超长文本 | 标题、内容、用户名 | 是否截断、Tooltip、换行 |
| 超长列表 | 商品列表、评论列表 | 分页、虚拟滚动、性能 |
| 空数据 | 无搜索结果、新用户 | Empty状态设计 |
| 大图片 | 用户头像、商品图 | 加载占位、压缩、懒加载 |
| 缺失图片 | 图片404 | 默认占位图 |
| 极小屏幕 | iPhone SE (375px) | 布局不错乱、可操作 |
| 极大屏幕 | 4K (3840px) | 内容居中、不过度拉伸 |

### 4.2 交互边界

#### 操作频率边界

```
从Figma交互设计推断需要测试的边界:

点击按钮 → 快速连续点击（防抖）
发送验证码 → 60秒倒计时内重复点击
搜索输入 → 每次输入都触发搜索（节流）
滚动加载 → 快速滚动到底部（防止重复请求）
```

#### 操作边界测试矩阵

| 操作类型 | 正常操作 | 边界操作 | 异常操作 |
|---------|---------|---------|---------|
| 点击 | 单次点击 | 双击、长按、快速连击 | 网络慢时连续点击 |
| 输入 | 正常输入 | 复制粘贴、拖拽文本 | 输入中断网 |
| 滚动 | 缓慢滚动 | 快速滚动到底 | 滚动中切换页面 |
| 拖拽 | 正常拖拽 | 拖出边界、反向拖拽 | 拖拽中释放鼠标 |

### 4.3 数据边界

#### 数值边界

```
从Figma设计推断数值范围:

商品价格: ¥0.01 - ¥999,999.99
  → 测试: 0, 0.01, 0.001, 999999.99, 1000000

用户年龄: 1-120岁
  → 测试: 0, 1, 18, 120, 121, -1

库存数量: 0-9999
  → 测试: 0, 1, 9999, 10000, -1
```

## 第5层：隐藏需求挖掘

### 5.1 从设计推断后端接口

#### 推断规则

| Figma设计特征 | 推断的后端接口 | 测试重点 |
|--------------|---------------|---------|
| 列表页 | GET /api/items | 分页、筛选、排序参数 |
| 详情页 | GET /api/items/:id | ID不存在、权限校验 |
| 表单提交 | POST /api/items | 参数校验、重复提交 |
| 编辑页 | PUT /api/items/:id | 并发修改、乐观锁 |
| 删除按钮 | DELETE /api/items/:id | 关联数据、软删除 |
| 搜索框 | GET /api/items?keyword= | 特殊字符、SQL注入 |
| 实时更新 | WebSocket连接 | 断线重连、消息序列 |

#### 示例推断

```
Figma设计: 用户列表页 + 搜索 + 筛选 + 排序

推断接口:
GET /api/users?
  keyword=xxx        # 关键词搜索
  &status=active     # 状态筛选
  &role=admin        # 角色筛选
  &sort=created_at   # 排序字段
  &order=desc        # 排序方向
  &page=1            # 页码
  &pageSize=20       # 每页数量

生成测试用例:
TC001: 只传page和pageSize，验证默认列表
TC002: 传keyword，验证搜索功能
TC003: 传status=active，验证筛选功能
TC004: 同时传多个筛选条件，验证组合筛选
TC005: 传sort和order，验证排序功能
TC006: 传page=0，验证边界处理
TC007: 传pageSize=10000，验证大数据量
TC008: keyword传SQL注入字符，验证安全性
```

### 5.2 从交互推断业务规则

#### 推断技巧

```
设计显示: "提交"按钮在所有字段填写完成后才可点击
→ 推断业务规则: 前端实时校验 + 按钮状态联动
→ 测试场景: 
  - 部分字段为空时按钮是否禁用
  - 字段格式错误时按钮是否禁用
  - 修改已填写字段后按钮状态是否更新

设计显示: "发送验证码"按钮点击后变为60秒倒计时
→ 推断业务规则: 防止频繁发送 + 本地倒计时
→ 测试场景:
  - 倒计时期间按钮是否禁用
  - 倒计时结束后按钮是否恢复
  - 刷新页面后倒计时是否重置
  - 多个标签页的倒计时是否同步

设计显示: 购物车商品数量右上角显示红点
→ 推断业务规则: 实时更新 + 本地存储或接口轮询
→ 测试场景:
  - 添加商品后红点数字是否立即更新
  - 多个标签页同时操作时数字是否同步
  - 刷新页面后数字是否保持
  - 登出后红点是否清除
```

### 5.3 从文案推断用户心智

#### 文案分析

```
设计文案: "立即购买" vs "加入购物车"
→ 推断用户心智: 
  - "立即购买" = 快速下单，跳过购物车
  - "加入购物车" = 继续浏览，稍后结算
→ 测试场景:
  - 点击"立即购买"应直接跳转到结算页
  - 点击"加入购物车"应停留在当前页或弹窗提示
  - 两个按钮的视觉优先级应符合业务期望

设计文案: "保存草稿" + "发布"
→ 推断用户心智:
  - 保存草稿 = 暂存，不公开
  - 发布 = 正式上线，他人可见
→ 测试场景:
  - 草稿状态的内容他人是否不可见
  - 发布后的内容是否立即对他人可见
  - 是否支持从草稿恢复编辑
  - 是否支持已发布内容再次变回草稿

设计文案: "× 关闭" vs "← 返回"
→ 推断用户心智:
  - 关闭 = 退出当前流程，可能丢失未保存内容
  - 返回 = 回到上一步，保留已填写内容
→ 测试场景:
  - 点击关闭是否有"确认离开"提示
  - 点击返回是否保留已输入的内容
  - 关闭后再次进入是否清空内容
```

## 实战案例：完整分析一个注册页

### Figma设计概览

```
页面标题: 注册账号

[邮箱地址] *
[请输入邮箱地址.........................]
💡 将用于接收验证邮件和登录

[密码] *
[请输入密码(8-20位)...................]  👁️
💡 需包含字母和数字

[昵称]
[请输入昵称(2-20字符).................]
💡 可以使用中文、英文

[ ] 我已阅读并同意《用户协议》和《隐私政策》

[立即注册 →]

已有账号？去登录
```

### 完整分析输出

#### 1. 结构分析
- ✅ 单页表单设计
- ✅ 3个输入字段（邮箱、密码、昵称）
- ✅ 1个复选框（协议）
- ✅ 1个提交按钮
- ✅ 1个跳转链接（去登录）

#### 2. 交互分析
- ✅ 邮箱：必填，格式校验，实时校验
- ✅ 密码：必填，长度8-20，字母+数字，可显示/隐藏
- ✅ 昵称：选填，长度2-20，中英文
- ✅ 协议：必须勾选，可点击查看详情

## 总结：Figma分析的黄金法则

1. **不要只看表面** - 一个输入框背后可能有10个测试场景
2. **推断要有依据** - 每个推断都要标注"从哪里看出来的"
3. **不确定就标记** - 遇到模棱两可的，标记为"待确认"
4. **关联起来看** - 页面之间的跳转关系也是测试点
5. **用户视角思考** - 用户会怎么用？会怎么滥用？
6. **经验库辅助** - 类似的功能历史上出过什么问题？

**记住**: Figma设计稿是**测试分析的起点**，不是终点。
