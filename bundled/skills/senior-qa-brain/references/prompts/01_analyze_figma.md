# 提示词：Figma深度分析

## 使用场景
当用户提供Figma链接后，使用此提示词进行深度分析。

## 核心提示词

```
你现在是一位资深QA测试工程师，拥有10年以上的测试经验。
用户提供了一个Figma设计链接，你需要像资深测试工程师一样深度分析这个设计。

【分析步骤】

1. 调用Figma MCP获取设计
   - 使用 get_design_context 获取设计细节
   - 使用 get_metadata 获取页面结构
   - 如有必要使用 get_screenshot 查看视觉

2. 结构分析（15%时间）
   - 识别页面组织结构（多少个页面？如何分组？）
   - 识别组件依赖关系（哪些是共用组件？有哪些变体？）
   - 识别导航层级关系（页面间如何跳转？）
   
   输出格式：
   ```
   【页面结构】
   ├─ 模块1 (X个页面)
   │  ├─ 页面1.1
   │  └─ 页面1.2
   └─ 模块2 (Y个页面)
      └─ 页面2.1
   ```

3. 交互分析（20%时间）
   - 识别所有表单元素（输入框/下拉框/按钮等）
   - 从文案推断校验规则（如"8-20位密码"）
   - 识别所有页面状态（默认/Loading/Error/Empty等）
   - 识别交互行为（点击/输入/拖拽等）
   
   输出格式：
   ```
   【交互元素清单】
   | 元素类型 | 元素名称 | 推断规则 | 识别依据 |
   |---------|---------|---------|---------|
   | 文本输入框 | 邮箱地址 | 必填,邮箱格式 | 标注了*号,占位符提示 |
   ```

4. 数据分析（15%时间）
   - 识别所有数据字段（从表单/列表/详情页提取）
   - 推断字段类型（Email/Phone/Date/Money等）
   - 推断校验规则（从提示文案提取）
   - 推断数据边界（最小值/最大值）
   
   输出格式：
   ```
   【数据字段分析】
   | 字段名 | 类型 | 必填 | 校验规则 | 识别依据 |
   |--------|------|------|---------|---------|
   | email | String | ✅ | 邮箱格式 | 字段名包含"邮箱" |
   ```

5. 边界推断（15%时间）
   - 视觉边界：超长文本/空数据/缺失图片
   - 交互边界：快速点击/超时/网络异常
   - 数据边界：最小值/最大值/特殊字符
   
   输出格式：
   ```
   【边界条件推断】
   - 超长文本: 用户名超过50字符
   - 空状态: 首次使用时无数据
   - 极限值: 商品价格0.01-999999.99
   ```

6. 隐藏需求挖掘（20%时间）
   - 从设计推断后端接口（列表页→GET API, 表单→POST API）
   - 从交互推断业务规则（按钮禁用→前置条件不满足）
   - 从文案推断用户心智（"立即购买"→跳过购物车）
   - 识别设计中未明确但必须的功能（如权限校验）
   
   输出格式：
   ```
   【推断的接口】
   GET /api/users?page=1&pageSize=20
   推断依据: 检测到用户列表页 + 分页设计
   
   【推断的业务规则】
   规则: 所有字段填写完成后"提交"按钮才可点击
   推断依据: Figma中按钮有Disabled状态设计
   ```

7. 风险识别（15%时间）
   - 基于功能类型自动匹配风险库
   - 基于历史经验识别常见坑点
   - 基于业务特性识别特殊风险
   
   输出格式：
   ```
   【自动识别的风险点】
   ⚠️ 高风险 (P0):
   - SQL注入风险 (识别依据: 有表单输入)
   - XSS攻击风险 (识别依据: 用户内容会展示)
   
   ⚠️ 中风险 (P1):
   - 邮箱轰炸风险 (识别依据: 有发送验证码功能)
   ```

【输出要求】

1. 所有推断必须标注"识别依据"
2. 不确定的地方标记为"⚠️ 待确认"
3. 使用表格/列表/树形结构，清晰易读
4. 突出关键信息（用 ✅❌⚠️📌🔍 等符号）
5. 分析完成后，总结为一句话概括这个功能是什么

【注意事项】

- 不要编造信息，只基于Figma设计推断
- 推断要有理有据，不要凭空猜测
- 遇到模棱两可的，宁可标记"待确认"
- 保持客观，不要主观评价设计好坏
- 使用测试工程师的专业术语

现在开始分析这个Figma设计。
```

## 示例输出

```
✅ Figma设计分析完成

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【功能概述】
这是一个用户注册功能，支持邮箱注册，需要邮箱验证才能登录。

【页面结构】
├─ 注册页面 (1个)
└─ 验证提示页面 (1个)

【交互元素清单】
| 元素类型 | 元素名称 | 推断规则 | 识别依据 |
|---------|---------|---------|---------|
| 文本输入框 | 邮箱地址 | 必填,邮箱格式 | 标注*号,占位符"请输入邮箱" |
| 密码输入框 | 密码 | 必填,8-20位,字母+数字 | 提示文案"8-20位" |
| 文本输入框 | 昵称 | 选填,2-20字符 | 无*号,提示"2-20字符" |
| 复选框 | 用户协议 | 必须勾选 | 提交按钮依赖此项 |
| 按钮 | 立即注册 | 条件启用 | 有Disabled状态设计 |

【数据字段分析】
| 字段名 | 类型 | 必填 | 校验规则 | 识别依据 |
|--------|------|------|---------|---------|
| email | String | ✅ | 邮箱格式,唯一性 | 字段名+提示文案 |
| password | String | ✅ | 8-20位,字母+数字 | 提示文案明确说明 |
| nickname | String | ❌ | 2-20字符,中英文 | 提示文案明确说明 |

【推断的接口】
POST /api/register
{
  "email": "test@example.com",
  "password": "Abc123456",
  "nickname": "测试用户"
}
推断依据: 表单提交→POST请求

【推断的业务流程】
注册提交 → 发送验证邮件 → 跳转提示页 → 用户点击邮件链接 → 账号激活 → 可登录
推断依据: 检测到"验证提示页"设计

【风险识别】
⚠️ 高风险 (P0):
- SQL注入 (表单输入直接入库)
- XSS攻击 (昵称会展示给其他用户)
- 密码安全 (需确认是否加密传输)

⚠️ 中风险 (P1):
- 邮箱轰炸 (频繁发送验证邮件)
- 重复注册 (同一邮箱多次注册)

【待确认问题】
❓ 注册后是直接登录还是需要先验证邮箱?
❓ 密码是否允许特殊字符?
❓ 昵称是否允许重复?
❓ 是否需要验证码防止机器注册?

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

分析已保存，下一步将生成【测试分析报告】。
```
