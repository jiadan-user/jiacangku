# 实用测试规则 - 基于80/20原则

> 用20%的精准测试，发现80%的风险

---

## 核心理念

### 黄金法则
- ✅ **Top 10-15%的测试用例可发现75-90%的重大缺陷**
- ✅ **测试用户可见行为，不测实现细节**
- ✅ **不测试第三方依赖和无法控制的内容**
- ✅ **覆盖率目标：需求覆盖≥95%（不追求100%）**

### 用例数量指南

| 功能规模 | 推荐用例数 | 说明 |
|---------|----------|------|
| 小功能（1-3个页面） | 20-30条 | 核心流程 + 关键异常 |
| 中等功能（4-8个页面） | 40-60条 | 核心流程 + 常见场景 + 关键异常 |
| 大功能（9+个页面） | 80-100条 | 完整覆盖但排除极端场景 |

**重要**：如果生成超过100条用例，说明粒度太细或包含了过多不实用的场景。

## 必测场景清单（P0/P1）

### 1. 核心功能正常流程
```
✅ 主流程Happy Path（1-3条用例）
✅ 关键分支流程（每个分支1条）
❌ 不测：理论上可能但用户不会走的路径
```

**示例（登录功能）**：
- ✅ TC001: 正确账号密码登录
- ✅ TC002: 错误密码登录
- ✅ TC003: 忘记密码流程
- ❌ 不测：连续输入错误密码100次后的复杂逻辑

### 2. 表单校验（实用边界）
```
✅ 必填项为空
✅ 格式校验（邮箱、手机号）
✅ 明显边界（最小长度、最大长度）
❌ 不测：10000字符超长输入、10层嵌套JSON
```

**示例（用户名输入）**：
- ✅ TC010: 用户名为空提交
- ✅ TC011: 用户名3位（最小长度）
- ✅ TC012: 用户名20位（最大长度）
- ❌ 不测：用户名1000位（极端场景）
- ❌ 不测：用户名包含emoji表情组合字符（除非产品明确支持）

### 3. 基础安全测试（简化版）
```
✅ SQL注入：测试1-2个典型payload
✅ XSS攻击：测试1个基础<script>标签
✅ 越权访问：测试横向越权（改用户ID）
❌ 不测：20种SQL注入变体、复杂的XSS绕过技巧
```

**示例（搜索框）**：
- ✅ TC030: 输入 `' OR '1'='1` 验证过滤
- ✅ TC031: 输入 `<script>alert('xss')</script>` 验证转义
- ❌ 不测：SQL注入向量库的全部20个变体
- ❌ 不测：编码绕过、Unicode混淆等高级攻击

### 4. 常见错误处理
```
✅ 网络错误（断网/超时）
✅ 服务器错误（500/502/503）
✅ 权限错误（401/403）
❌ 不测：各种HTTP状态码的完整矩阵测试
```

**示例**：
- ✅ TC040: 断网后提交表单，验证友好提示
- ✅ TC041: 接口返回500，验证错误提示
- ✅ TC042: 登录过期访问，验证跳转登录
- ❌ 不测：408/409/410等不常见状态码

### 5. 基础权限检查
```
✅ 未登录访问需要登录的页面
✅ 普通用户访问管理员功能
✅ 横向越权（修改他人数据）
❌ 不测：复杂的RBAC权限矩阵全量组合
```

## 可选场景清单（P2/P3）

### 1. 并发场景（简化版）
```
✅ 重复点击按钮（防抖测试）
✅ 双开浏览器标签页（会话同步）
❌ 不测：1000人同时操作的压力测试
❌ 不测：复杂的分布式事务场景
```

**示例**：
- ✅ TC050: 快速点击提交按钮5次，验证只提交1次
- ✅ TC051: 两个标签页同时登录，验证会话处理
- ❌ 不测：模拟1000个并发用户的秒杀场景

### 2. 兼容性测试（主流环境）
```
✅ Chrome（最新版）
✅ Safari（最新版）
✅ 移动端（iOS/Android各1个）
❌ 不测：IE11、Firefox 50等老版本
❌ 不测：全部浏览器版本的矩阵组合
```

### 3. 特殊字符（实用场景）
```
✅ 空格、换行符
✅ 常见中文符号（，。！？）
❌ 不测：零宽字符、RTL字符、控制字符
❌ 不测：所有Unicode字符集
```

## 不应该测试的场景（明确排除）

### 1. 第三方依赖
```
❌ 微信/Google/Facebook登录的完整流程
❌ 支付宝/微信支付的真实支付
❌ 第三方地图API的所有功能
```

**替代方案**：Mock第三方接口，只测试集成点

### 2. 无法控制的内容
```
❌ 第三方网站的链接是否有效
❌ CDN资源的加载速度
❌ 外部API的响应时间
```

### 3. 极端理论场景
```
❌ 10000层嵌套的JSON解析
❌ 100GB文件上传
❌ 1000万条数据的前端渲染
❌ 100年后的日期计算
```

**原则**：如果用户实际使用中不会遇到，就不要测试

### 4. 过度细分的组合
```
❌ 全量正交表组合测试
❌ 所有字段的笛卡尔积组合
❌ 所有边界值的两两组合
```

**替代方案**：只测高频组合和高风险组合

## 安全测试实用指南

### SQL注入（精简版）
测试**1-2个**典型payload即可：
```sql
-- Payload 1: 基础注入
' OR '1'='1

-- Payload 2: 注释绕过（可选）
admin'--
```

**不测试**：
- ❌ 时间盲注
- ❌ 布尔盲注
- ❌ 堆叠查询
- ❌ 宽字节注入
- ❌ 二次注入

**理由**：如果基础payload被拦截，说明防护机制有效；如果基础payload通过了，高级payload也会通过。

### XSS攻击（精简版）
测试**1个**基础payload即可：
```html
<script>alert('xss')</script>
```

**不测试**：
- ❌ 编码绕过（URL编码、Base64、Unicode）
- ❌ DOM型XSS的复杂利用
- ❌ CSS注入
- ❌ SVG注入

### 越权测试（实用版）
只测试**横向越权**（最常见）：
```
✅ 修改URL参数：/user/123 → /user/456
✅ 修改接口参数：{userId: 123} → {userId: 456}
❌ 不测：复杂的RBAC权限组合矩阵
```

## 边界值测试实用指南

### 长度边界（简化版）
假设字段限制：8-20位

**只测3个值**：
```
✅ 7位（边界-1，应该失败）
✅ 8位（最小值，应该成功）
✅ 20位（最大值，应该成功）

不测试：
❌ 21位（边界+1）- 如果最大值测试通过，+1通常也会被拦截
❌ 9位、19位 - 中间值没有额外价值
❌ 1000位 - 极端场景，实际不会发生
```

### 数值边界（简化版）
假设年龄限制：18-65岁

**只测3个值**：
```
✅ 17岁（边界-1）
✅ 18岁（最小值）
✅ 65岁（最大值）

不测试：
❌ 66岁（边界+1）- 通常与17岁逻辑一致
❌ 0岁、-1岁、120岁 - 极端场景
❌ 17.5岁 - 小数处理（除非产品支持）
```

## 用例质量评估标准

### 好的测试用例特征
```
✅ 覆盖真实用户场景
✅ 验证核心业务价值
✅ 失败时能快速定位问题
✅ 步骤清晰，可重复执行
✅ 优先级标注合理（P0/P1/P2/P3）
```

### 差的测试用例特征
```
❌ 测试用户不会做的操作
❌ 测试无法控制的第三方内容
❌ 步骤过于复杂，依赖多个前置条件
❌ 验证点模糊，无法判断成功/失败
❌ 极端场景但实际发生概率接近0
```

## 实用性自检清单

生成用例后，问自己：

### 用例数量
- [ ] 小功能是否≤30条？
- [ ] 中等功能是否≤60条？
- [ ] 大功能是否≤100条？
- [ ] 如果超过100条，是否包含了过多极端场景？

### 场景实用性
- [ ] 每个测试场景是否是用户真实会遇到的？
- [ ] 是否排除了第三方依赖的完整测试？
- [ ] 是否排除了无法控制的内容测试？
- [ ] 边界值测试是否只保留了明显边界？

### 安全测试
- [ ] SQL注入是否只保留了1-2个典型payload？
- [ ] XSS测试是否只保留了基础<script>标签？
- [ ] 是否排除了复杂的安全攻击向量？

### 并发测试
- [ ] 是否只保留了重复点击、双开标签页等简单场景？
- [ ] 是否排除了1000人并发的压测场景？

---

## 总结：实用测试的黄金原则

1. **20%精准测试，发现80%风险** - 质量>数量
2. **测试用户行为，不测实现细节** - 关注价值
3. **排除第三方和不可控内容** - 聚焦可控范围
4. **简化边界和安全测试** - 典型场景足够
5. **用例数量有上限** - 超过100条说明有问题
6. **问自己：用户会这样做吗？** - 如果不会，别测

**记住**：测试的目标是建立信心和发现风险，不是追求覆盖率数字。
