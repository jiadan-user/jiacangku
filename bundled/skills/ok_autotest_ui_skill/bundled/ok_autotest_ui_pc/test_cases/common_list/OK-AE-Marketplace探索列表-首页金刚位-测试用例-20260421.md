### 模块 D：排序（Best Match / Newest First / Lowest Price / Highest Price）与 sortId

**探测摘要（AE Marketplace `cate-marketplace` 列表页 SSR，2026-04-21）**  
页面内嵌 `sortList` 与下拉文案一致，**sortId 取值如下（与筛选项一一对应）**：

| 筛选项（文案） | sortId | 预期排序语义（对列表结果抽样校验） |
|----------------|--------|-----------------------------------|
| Best Match | **0** | 平台默认相关度/综合排序（以产品规则为准） |
| Newest First | **1** | 新发优先（发布时间降序，或产品等价字段） |
| Lowest Price | **3** | 标价从低到高（同价并列顺序以产品为准） |
| Highest Price | **4** | 标价从高到低 |

**说明**：sortId **2** 在当日 SSR 中未出现在 `sortList`；自动化可覆盖非法值（如 `sortId=2`、`sortId=999`）降级行为。  
**URL**：切换排序后，应校验当前页 URL 中 **`sortId` 与所选项一致**，且 **同一查询串内 `sortId` 仅出现一次**；若线上仅为前端状态、地址栏无 `sortId`，则以「列表/API 返回顺序与上表语义一致」为验收，并记录环境差异。

**Price 范围**：以下 **TC022～TC024** 仅覆盖价格面板三种输入方式——**只填最小**、**只填最大**、**同时填最小与最大**；不测其它组合或非法输入（如有单端校验以产品为准）。

---

### TC022: Price — 仅输入最小值（Min）

#### 📋 前置条件
- 筛选行含 **Price**；进入自定义输入态后存在 **Min**（或等价占位）输入框。

#### 🎬 执行步骤
1. 点击 **Price** 打开面板，**仅输入 Min** 为合法数值（如 `100`）。  
2. **不填写 Max**（max如有内容则清空 Max）。  
3. 点击应用 / Apply / 确定（以线上为准）。

#### ✅ 预期结果
- 筛选项或 Tag 反映「下限」或等价文案；列表结果符合「不低于所填最小值」等产品定义。  
- 页面不报错；若产品要求必须两端都填，应有明确提示（记录实际规则）。

#### 📊 用例属性
- **优先级**: P0
- **测试类型**: 功能测试
- **UI自动化**: ✅ 可自动化
