## 需求变更说明（2026-05-12）

### Contact 按钮交互规则（新增，2026-05-12更新）

以下规则适用于**Contact 按钮**的点击行为，用于区分会话身份与联系历史状态：

| 用户状态 | 是否点击过Contact | 点击 Contact | 预期行为 |
|----------|-----------------|-------------|----------|
| **从未在本设备/本会话登录过**（纯访客） | - | 进入微聊 | 打开微聊页面，以**未登录用户发起的微聊**（访客会话/guest chat，URL 可能含 `chat-guest`、`needLogin` 等参数） |
| **当前已登录** | - | 进入微聊 | 打开微聊页面，以**已登录用户发起的微聊** |
| **曾登录后退出登录** | ✅ **登录期间点击过Contact**（已建立联系记录） | 引导登录 | **不**直接进入微聊；应弹出登录引导（登录弹层/登录页等），登录成功后再按产品规则进入沟通 |
| **曾登录后退出登录** | ❌ **登录期间未点击Contact**（未建立联系记录） | 进入访客微聊 | 打开微聊页面，以**未登录用户发起的微聊**（与纯访客行为一致） |

**核心业务规则**：
- 系统通过客户端状态（如特定Cookie或localStorage）记录「用户曾联系过此发布者」
- **仅在登录后点击过Contact时才记录联系状态**
- 退出登录后保留此联系状态，用于区分「纯访客」、「曾建立联系后退出的用户」和「仅登录未联系过的用户」

### 发布者头像/昵称交互规则（保持原有逻辑）

点击**发布者用户名或头像** → 跳转到**发布者账户主页/店铺页**（原有逻辑保持不变）

**说明**：**listings / sold 文案**是否可点击、跳转目标是否仍为店铺列表，以产品最新说明为准（见 TC-PUB-016）。
