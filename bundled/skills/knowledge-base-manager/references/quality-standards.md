# 质量标准与去重策略

## 质量标准

### 五大质量维度

#### 1. 完整性（Completeness）

**检查项**：
- ✅ 文件不为空，每个章节有实际内容
- ✅ 没有"待补充"占位符
- ✅ 关键字段有说明
- ✅ 规则有示例（如适用）
- ✅ 有元数据（来源、更新时间）

**评分标准**：
- 5分：内容完整，有示例，有说明
- 3分：内容基本完整，部分章节简略
- 1分：只有标题或"待补充"
- 0分：文件为空

#### 2. 准确性（Accuracy）

**检查项**：
- ✅ 规则描述清晰无歧义
- ✅ 数值、参数准确
- ✅ 逻辑一致，无矛盾
- ✅ 术语使用规范

**常见问题**：
- ❌ 模糊表述："大约60秒" → 应为"60秒"
- ❌ 不一致："验证码60秒" vs "验证码1分钟"
- ❌ 过时信息：规则已变更但未更新

#### 3. 一致性（Consistency）

**检查项**：
- ✅ 格式统一（标题层级、列表符号）
- ✅ 术语统一（同一概念用词一致）
- ✅ 结构统一（同类文件结构相似）
- ✅ 引用格式统一

**示例**：
```markdown
✅ 统一使用：验证码、有效期、60秒
❌ 混用：验证码/verification code、过期时间/有效期、60秒/1分钟
```

#### 4. 可维护性（Maintainability）

**检查项**：
- ✅ 文件大小合理（< 600 行）
- ✅ 章节划分清晰
- ✅ 有变更历史记录
- ✅ 有交叉引用
- ✅ 避免硬编码路径

#### 5. 可发现性（Discoverability）

**检查项**：
- ✅ 文件命名清晰
- ✅ 有索引文件
- ✅ 有交叉引用
- ✅ 关键词明确

### 质量检查流程

**自查清单**：
```markdown
- [ ] 内容完整（非"待补充"）
- [ ] 格式正确（Markdown 语法有效）
- [ ] 有元数据（来源、更新时间）
- [ ] 内容具体（非模糊描述）
- [ ] 有示例（如适用）
- [ ] 无重复内容
- [ ] 术语统一
- [ ] 逻辑一致
```

## 去重策略

### 去重级别

#### Level 1: 精确匹配（Exact Match）

**定义**：文本完全相同（忽略空白和标点）

**判断标准**：
- 标准化后文本一致
- 关键信息点完全相同

**处理**：
- ✅ 跳过写入
- 📝 记录：内容已存在于 XXX 位置

**示例**：
```
文本A: "验证码有效期60秒"
文本B: "验证码有效期 60 秒。"
判定: 精确匹配 → 跳过
```

#### Level 2: 语义等价（Semantic Equivalent）

**定义**：表述不同但含义完全相同

**判断标准**：
- 核心规则参数相同
- 逻辑完全一致
- 仅表述方式不同

**处理**：
- 🔄 合并为更完整的版本
- 📋 保留信息量更大的表述

**示例**：
```
文本A: "验证码60秒后过期"
文本B: "验证码有效期为60秒"
判定: 语义等价 → 合并为"验证码有效期60秒，超时后失效"
```

#### Level 3: 规则冲突（Rule Conflict）

**定义**：同一规则的不同取值

**判断标准**：
- 规则主体相同
- 参数值不同
- 可能是版本变更

**处理**：
- ⚠️ 标记冲突
- 📅 检查时间戳
- 👤 询问用户确认最新版本

**示例**：
```
文本A: "验证码有效期60秒"（来源：v1.0, 2026-01-15）
文本B: "验证码有效期90秒"（来源：v2.0, 2026-03-23）
判定: 规则冲突 → 标记并询问用户
```

#### Level 4: 互补内容（Complementary）

**定义**：不同层次的相关内容

**判断标准**：
- 描述同一事物
- 但处于不同抽象层次
- 或不同关注点

**处理**：
- ✅ 两处都保留
- 🔗 添加交叉引用

**示例**：
```
业务规则层: "验证码有效期60秒"（规则定义）
测试知识层: "验证码过期场景：获取验证码→等待61秒→输入→提示过期"（测试场景）
判定: 互补内容 → 都保留，添加引用
```

### 去重判断流程

```
1. 读取目标文件内容
   ↓
2. 语义分析新内容与已有内容
   ↓
3. 判断关系类型：
   ├─ 精确匹配？ → 跳过
   ├─ 语义等价？ → 合并
   ├─ 规则冲突？ → 标记冲突
   └─ 互补内容？ → 都保留
   ↓
4. 执行相应操作
```

### 冲突标记格式

```markdown
## 验证码规则

⚠️ **规则冲突 - 需确认**

**版本 A**（来源：用户登录测试用例-v2.md, 2026-01-15）
- 有效期：60秒

**版本 B**（来源：登录优化需求文档.md, 2026-03-23）
- 有效期：90秒

**待确认**：请确认当前生效版本。
```

### 跨层级去重

**原则**：不同层级的内容通常是互补的，不是重复

**示例**：
```
产品架构层: "用户模块包含：注册、登录、个人信息管理"（模块定义）
业务规则层: "登录验证码有效期60秒"（具体规则）
测试知识层: "登录验证码过期测试场景"（测试场景）

判定: 三者都保留，属于不同层次的互补内容
```

### 跨站点去重

**原则**：站点差异是有价值的信息，应保留

**处理方式**：
- 通用规则 → 放在通用规则/
- 站点差异 → 放在站点差异/，或在通用规则中用表格标注

**示例**：
```markdown
## 货币显示规则

### 通用规则
- 小数位：2位
- 负数：用 - 号表示

### 站点差异

| 站点 | 千分位 | 货币符号位置 |
|------|--------|------------|
| US   | 无     | 前置 $1234.56 |
| EU   | 有     | 后置 1.234,56€ |
| CN   | 有     | 前置 ¥1,234.56 |
```

## 质量评分

### 评分公式

```
总分 = 完整性 × 0.3 + 准确性 × 0.3 + 一致性 × 0.2 + 可维护性 × 0.1 + 可发现性 × 0.1
```

### 评分等级

- **90-100分**：优秀 ✅
- **75-89分**：良好 👍
- **60-74分**：合格 ⚠️
- **< 60分**：需改进 ❌
