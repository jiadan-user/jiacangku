# 知识库文档模板

本文档包含了知识库中各类文档的标准模板。在生成或更新文档时，必须严格遵循这些模板的结构和格式。

## 1. 业务规则文档模板（7章）

```markdown
# <功能名>规则

## 1. 功能概述
- 业务价值
- 用户角色
- 入口位置

## 2. 核心流程
- 主流程
- 异常流程

## 3. 业务规则
- 3.1 输入规则
- 3.2 校验规则
- 3.3 权限规则
- 3.4 业务约束

## 4. 错误处理
- 4.1 错误码定义
- 4.2 错误提示文案

## 5. 依赖模块
- 上游依赖（谁调用我）
- 下游依赖（我调用谁）
- 跨域交互说明

## 6. 已知问题
- 产品待确认问题
- 技术风险

## 7. 变更历史
| 日期 | 版本 | 变更内容 | 变更人 |
```

## 2. 业务流程文档模板（5章）

```markdown
# <流程名>业务流程

> **业务目标**：一句话描述

## 1. 完整流程图

> **要求**：专注于本业务域内的详细步骤，**不包含**跨域交互的复杂逻辑分支（跨域逻辑统一在业务全景文档中展示）。

\`\`\`mermaid
graph TD
    A[开始] --> B[步骤1]
    B --> C{判断}
    C -->|是| D[步骤2]
    C -->|否| E[异常处理]
\`\`\`

## 2. 详细步骤与观测点

### 步骤1：<步骤名>
- **页面位置**：

  - ✅ P0观测点
  - ❌ 负向观测点
- **验证方法**：
- **关联规则**：

## 3. 流程完整性验证清单

- [ ] 验证点1

## 4. 关联文档

- [业务全景](./业务全景.md)

```

## 3. 业务全景文档模板（11章）

```markdown
# <模块名>业务全景

## 1. 业务定位
- 业务价值
- 目标用户

## 2. 业务范围
- 功能覆盖
- 地域覆盖
- 用户角色

## 3. 业务流程全景图

> **要求**：全景图必须**详细展示跨域交互与依赖的逻辑分支**。例如：如果涉及钱包，必须画出"未绑定钱包"和"已绑定钱包"的分支；如果涉及AI，必须画出调用AI服务和降级处理的分支。

\`\`\`mermaid
graph TD
    subgraph 卖家侧
        A[操作] --> B{是否绑定钱包?}
        B -->|未绑定| C[跳转绑定钱包]
        B -->|已绑定| D[继续流程]
    end
    subgraph 买家侧
    end
    subgraph 外部依赖
        钱包系统
        AI服务
    end
    C -.->|调用| 钱包系统
    D -->|结算| 钱包系统
    A --> E{调用AI?}
    E -->|成功| F[展示AI结果] -.-> AI服务
    E -->|失败| G[降级处理]
\`\`\`
```
