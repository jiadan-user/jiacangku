# 知识库管理器

## 概述

将测试用例、需求文档转化为结构化知识库，自动生成业务规则、业务流程、业务全景和业务域关联。

## 快速开始

```bash
# 归档测试用例
使用 knowledge-base-manager 帮我把 @test-cases.md 归档到知识库

# 同步更新变更
登录验证码有效期从60秒改为90秒，帮我同步更新知识库
```

## 知识库架构

标准三层架构（自动识别）：
```
产品知识库/
├── 产品全景/          # 顶层产品设计
├── 业务知识图谱/      # 业务全景 + 业务流程 + 业务域关联
└── 业务规则库/        # 详细业务规则
```

## 核心功能

### 1. 自动归档

读取输入文档 → 提取业务规则 → 生成业务流程 → 生成业务全景 → 更新业务域关联

**输出**：
- `业务规则库/<模块名>/<功能名>规则.md` - 7章结构
- `业务知识图谱/<模块名>业务域/<流程名>业务流程.md` - 5章结构
- `业务知识图谱/<模块名>业务域/<模块名>业务全景.md` - 11章结构
- `业务知识图谱/业务域关联图.md` - 业务域之间的依赖关系和数据流转

### 2. 语义去重

使用 AI 理解判断重复内容，避免知识库冗余。

### 3. 同步更新

内容变更时自动同步更新：业务规则库 → 业务流程文档 → 业务全景文档 → 业务域关联图

### 4. 质量验证

自动检查：模板完整性、链接有效性、Mermaid 语法正确性

## 执行流程

### 归档流程

1. **读取模板** - **必须先使用 `Read` 工具读取 `references/document-templates.md` 获取最新模板**
2. **扫描架构** - 使用 `Shell` (如 `find`) 或 `Glob` 工具扫描知识库目录结构
3. **深度阅读与依赖分析** - 
   - 使用 `Read` 工具完整阅读输入文档，提取业务规则和流程
   - 分析当前知识库中已有的同类文档（如其他业务规则文档），确保生成的内容格式（如使用表格展示规则）与现有规范保持一致。
   - 分析上下游依赖（"这个功能会被谁用？"、"这个功能依赖谁？"）。例如：如果涉及交易，考虑钱包绑定状态；如果涉及内容发布，考虑是否依赖AI推荐。
4. **依赖爆炸半径分析与同步**
   - 分析当前模块被哪些下游业务域依赖（如：钱包提现依赖KYC）。
   - 使用 `StrReplace` 工具更新受影响的下游业务域的《业务全景文档》，在其全景图中补充跨域交互分支。
5. **语义去重** - 检测是否已有相似内容
6. **生成文档** - 使用 `Write` 工具按顺序生成（将跨域逻辑统一在全景文档中展示）：
   - 业务规则文档（7章，在"依赖模块"中说明跨域交互）
   - 业务流程文档（5章，详细版，专注于域内逻辑）
   - 业务全景文档（11章，精简版，全景图详细画出跨域交互的逻辑分支，如未绑定钱包的走向、AI降级等）
   - 业务域关联图（如涉及跨域关联，更新全局关联图）
7. **生成预览** - 展示所有变更
8. **确认写入** - 等待用户确认后写入
9. **质量验证** - 检查模板完整性、链接有效性、Mermaid 语法

### 更新流程

1. **读取模板** - **必须先使用 `Read` 工具读取 `references/document-templates.md` 获取最新模板**
2. **识别变更范围与依赖影响** - 
   - 分析变更内容，识别影响的模块和文档
   - 思考依赖影响：如果修改了钱包接口，是否影响了二手交易？如果修改了AI推荐，是否影响了房产发布？
3. **依赖爆炸半径分析与同步**
   - 分析当前模块被哪些下游业务域依赖。
   - 使用 `StrReplace` 工具更新受影响的下游业务域的《业务全景文档》，在其全景图中补充跨域交互分支。
4. **同步更新** - 使用 `StrReplace` 工具按顺序更新（确保跨域逻辑同步更新）：
   - 业务规则库
   - 业务流程文档
   - 业务全景文档（更新全景图中的跨域详细分支）
   - 业务域关联图（如涉及跨域关联）
5. **生成预览** - 展示所有变更
6. **确认写入** - 等待用户确认后写入
7. **质量验证** - 检查一致性

## 业务域关联管理

### 关联类型

1. **数据流转关联** - 一个业务域的数据流向另一个业务域
   - 示例：二手交易订单完成 → 款项进入钱包余额

2. **功能依赖关联** - 一个业务域依赖另一个业务域的功能
   - 示例：房产发布页 → 依赖AI推荐类目功能

3. **流程串联关联** - 一个业务域的流程结束后触发另一个业务域的流程
   - 示例：订单支付完成 → 触发钱包入账流程
4. **业务类目区分**  - 同一功能涉及多页业务类目
   - 示例：AI推荐类目 → 涉及Jobs、Property、Marketplace、Services、Community、Cars

### 更新时机

每次归档或更新时，检查是否需要更新业务域关联图：
- ✅ 新增业务域
- ✅ 发现新的业务域关联关系
- ✅ 业务域关联关系变更
- ❌ 仅更新业务规则细节，不涉及跨域关联

## 最佳实践

### 归档时
- ✅ 先扫描架构，确保目录结构正确
- ✅ 完整阅读输入，不跳过任何细节
- ✅ 分析已有同类文档，确保生成格式（如表格）与现有规范一致
- ✅ 分析依赖爆炸半径，同步更新受影响的下游业务域
- ✅ 默认同时生成业务规则、业务流程、业务全景、业务域关联
- ✅ 严格遵循模板结构，不遗漏章节
- ✅ 生成预览后等待用户确认再写入

### 更新时
- ✅ 识别变更范围，同步更新所有受影响的文档
- ✅ 分析依赖爆炸半径，同步更新受影响的下游业务域
- ✅ 更新变更历史，记录日期、版本、变更内容
- ✅ 验证链接有效性，确保跨文档引用正确

### 常见错误
- ❌ 忽略已有文档格式规范，导致新生成的文档风格不一致
- ❌ 忽略依赖爆炸半径，只更新当前模块，忘记更新调用方的全景图
- ❌ 只更新业务规则库，忘记更新业务知识图谱
- ❌ 不遵循模板结构，遗漏章节
- ❌ Mermaid 语法错误
- ❌ 链接路径错误
