## 2. 跨域数据流转

### 2.1 订单款项流转（二手交易 → 钱包）

```mermaid
sequenceDiagram
    participant 买家
    participant 二手交易系统
    participant 钱包系统
    participant 卖家
    
    买家->>二手交易系统: 下单并支付
    二手交易系统->>二手交易系统: 订单状态：待发货
    卖家->>二手交易系统: 确认发货
    二手交易系统->>二手交易系统: 订单状态：待收货
    买家->>二手交易系统: 确认收货
    二手交易系统->>二手交易系统: 订单状态：已完成
    二手交易系统->>钱包系统: 款项结算
    钱包系统->>钱包系统: 余额增加
    卖家->>钱包系统: 提现到银行账户
```

### 2.2 KYC状态流转（用户域 → 钱包/交易域）

```mermaid
sequenceDiagram
    participant 卖家
    participant 用户系统
    participant 钱包系统
    participant 交易系统
    
    卖家->>用户系统: 提交KYC认证资料
    用户系统->>用户系统: 审核通过 (Verified)
    用户系统->>钱包系统: 同步KYC状态 (Verified)
    钱包系统->>钱包系统: 解锁提现权限
    用户系统->>交易系统: 同步KYC状态 (Verified)
    交易系统->>交易系统: 解锁收款/高优发布权限
```

### 2.3 AI功能调用（各业务域 → 通用业务域）

```mermaid
sequenceDiagram
    participant 发布页
    participant AI推荐服务
    participant 详情页
    participant AI自动回复服务
    
    发布页->>AI推荐服务: 上传图片/输入标题
    AI推荐服务->>发布页: 返回推荐类目
    发布页->>发布页: 用户选择类目并发布
    
    详情页->>详情页: 买家点击Contact

```

### 2.4 B 端职位发布与用户信息（UMC / 登录态）

```mermaid
sequenceDiagram
    participant 招聘方
    participant Biz发布前台
    participant 用户与UMC
    participant Jobs供给

    招聘方->>Biz发布前台: 打开发布入口（未登录）
    Biz发布前台->>用户与UMC: 跳转登录
    用户与UMC->>Biz发布前台: 登录成功 + 回跳 fromUrl
    招聘方->>Biz发布前台: 首次填写雇主信息
    Biz发布前台->>用户与UMC: 读取/校验邮箱、验证码等
    招聘方->>Biz发布前台: Confirm 雇主信息
    Biz发布前台->>Jobs供给: 创建/更新职位发布上下文
    招聘方->>Biz发布前台: Job Basic / Requirement / Detail / Post
    Biz发布前台->>Jobs供给: 发布职位
```

### 2.5 详情页发布者信息区域 Contact 交互流转（详情页模块 → 用户域 + 消息域）

```mermaid
sequenceDiagram
    participant 买家
    participant 详情页前端
    participant 客户端状态
    participant 用户系统
    participant 消息系统
    participant 卖家
    
    买家->>详情页前端: 访问商品详情页
    详情页前端->>用户系统: 获取发布者信息
    用户系统->>详情页前端: 返回发布者数据(用户名/认证状态/listings/sold)
    详情页前端->>详情页前端: 渲染发布者信息卡片
    
    买家->>详情页前端: 点击 Contact 按钮
    详情页前端->>客户端状态: 检查登录状态
    详情页前端->>客户端状态: 检查联系历史标记
    
    alt 当前已登录
        详情页前端->>消息系统: 请求进入聊天
        消息系统->>详情页前端: 返回聊天页面URL
        详情页前端->>客户端状态: 记录「曾联系过此发布者」
        详情页前端->>详情页前端: 跳转到 Messages 聊天页
    else 从未登录（纯访客）
        详情页前端->>消息系统: 请求进入访客微聊
        消息系统->>详情页前端: 返回访客微聊页面URL
        详情页前端->>详情页前端: 跳转到访客微聊页
    else 曾登录且点击过Contact（有联系标记）
        详情页前端->>用户系统: 触发登录引导
        用户系统->>详情页前端: 显示登录弹层/登录页
        买家->>用户系统: 完成登录
        用户系统->>详情页前端: 登录成功
        详情页前端->>消息系统: 请求进入聊天
        消息系统->>详情页前端: 返回聊天页面URL
        详情页前端->>详情页前端: 跳转到 Messages 聊天页
    else 曾登录但未点击Contact（无联系标记）
        详情页前端->>消息系统: 请求进入访客微聊
        消息系统->>详情页前端: 返回访客微聊页面URL
        详情页前端->>详情页前端: 跳转到访客微聊页
    end
    
    Note over 客户端状态: 联系状态通过Cookie/localStorage持久化<br/>退出登录后保留，用于区分访客类型
```

**关键交互说明**：
- **用户域依赖**：发布者信息（用户名/头像/认证标识/listings/sold数量）、登录状态检测、登录引导
- **消息域依赖**：聊天服务（已登录用户微聊）、访客微聊服务
- **客户端状态域**：联系历史标记（Cookie/localStorage），跨会话保持，用于判断是否引导登录
- **安全逻辑**：通过客户端状态区分4种访客类型，在「曾登录且点击过Contact」场景下引导登录，保护用户历史会话

## 3. 详情页模块与业务域关系矩阵

| 详情页功能区域 | 用户域 | 消息域 | 客户端状态域 | 核心依赖 |
|--------------|-------|-------|------------|---------|
| 发布者信息展示 | ✅ 发布者基础信息<br/>✅ 认证标识 | ❌ | ❌ | 用户信息服务<br/>认证服务 |
| 用户名/头像交互 | ✅ 发布者主页服务 | ❌ | ❌ | 发布者主页服务 |
| Contact按钮（已登录） | ✅ 登录状态检测 | ✅ 聊天服务 | ✅ 联系状态记录 | 聊天服务<br/>客户端状态管理 |
| Contact按钮（纯访客） | ❌ | ✅ 访客微聊服务 | ✅ 检查客户端状态 | 访客微聊服务 |
| Contact按钮（曾登录已联系退出） | ✅ 登录引导 | ⏸️ 登录后聊天服务 | ✅ 检查联系标记 | 登录服务<br/>客户端状态管理 |
| Contact按钮（曾登录未联系退出） | ❌ | ✅ 访客微聊服务 | ✅ 检查客户端状态 | 访客微聊服务 |

**依赖强度**：
- ✅ 强依赖（功能核心）
- ⏸️ 条件依赖（特定场景下）
- ❌ 无依赖
