# 产品知识库

> 结构化的业务知识管理系统，自动将测试用例、需求文档转化为业务规则、流程图和全景视图。

## 📁 知识库结构

```
产品知识库/
├── 产品全景/          # 顶层产品设计、架构图
├── 业务知识图谱/      # 各业务域的流程图和全景视图
│   ├── 房产业务域/
│   ├── 车辆业务域/
│   ├── 二手交易业务域/
│   ├── 招聘业务域/
│   ├── 钱包业务域/
│   ├── 用户业务域/
│   ├── 通用业务域/
│   └── 业务域关联图.md
└── 业务规则库/        # 详细的业务规则文档
    ├── 房产模块/
    ├── 车辆模块/
    ├── 商品模块/
    ├── 交易模块/
    ├── 招聘模块/
    ├── 钱包模块/
    ├── 用户模块/
    └── 通用规则/
```

## 🚀 快速使用

### 1. 归档测试用例

```bash
使用 knowledge-base-manager skill 帮我把 @test-cases.md 归档到知识库
```

**自动生成**：
- ✅ 业务规则文档（7章结构，详细规则表格）
- ✅ 业务流程文档（5章结构，域内详细流程图）
- ✅ 业务全景文档（11章结构，跨域交互全景图）
- ✅ 业务域关联图（跨域依赖和数据流转）

### 2. 同步更新变更

```bash
登录验证码有效期从60秒改为90秒，帮我同步更新知识库
```

**自动同步**：
- ✅ 更新业务规则库
- ✅ 更新业务流程文档
- ✅ 更新业务全景文档
- ✅ 更新业务域关联图（如涉及跨域）

## 📋 文档结构说明

### 业务规则文档（7章）
存放在 `业务规则库/<模块名>/` 目录下，包含：
1. 功能概述
2. 核心流程
3. 业务规则（表格形式）
4. 错误处理（错误码表格）
5. 依赖模块
6. 已知问题
7. 变更历史

### 业务流程文档（5章）
存放在 `业务知识图谱/<业务域>/` 目录下，包含：
1. 完整流程图（Mermaid，域内详细步骤）
2. 详细步骤说明
3. 关键观察点
4. 关联文档
5. 变更历史

### 业务全景文档（11章）
存放在 `业务知识图谱/<业务域>/` 目录下，包含：
1. 业务域概述
2. 核心功能清单
3. 业务流程全景图（Mermaid，跨域交互详细分支）
4. 核心业务规则
5. 页面拓扑结构
6. 业务上下文
7. 详细业务规则
8. 测试观察点
9. 外部依赖
10. 已知问题
11. 变更历史

### 业务域关联图
存放在 `业务知识图谱/业务域关联图.md`，包含：
1. 业务域全景关联图（整体架构 + 分层视图）
2. 跨域数据流转（序列图）
3. 变更历史

## 🎯 核心特性

### 1. 智能去重
使用 AI 语义理解，自动识别并合并重复内容。

### 2. 自动同步
内容变更时，自动同步更新所有相关文档，包括下游依赖的业务域。

### 3. 依赖分析
自动分析跨域依赖关系，确保业务全景图包含完整的跨域交互逻辑。

### 4. 质量验证
自动检查模板完整性、Mermaid 语法、链接有效性。

## 🔄 工作流程

```
输入文档 → 提取规则 → 生成流程 → 生成全景 → 更新关联 → 预览 → 确认 → 写入
```

每次归档都会：
1. 自动识别知识库架构
2. 语义去重检查
3. 分析依赖爆炸半径
4. 生成预览供确认
5. 质量验证后写入
