# KYC身份认证规则

## 1. 功能概述
- **业务价值**：用户通过上传身份证件进行实名认证，认证通过后可获得更高可见度、接收买家付款、使用钱包提现等高级功能。
- **用户角色**：已登录的卖家（Seller）
- **入口位置**：`/biz/en/pay/identification`

## 2. 核心流程
- **主流程**：访问引导页 -> 选择上传证件（OCR识别）或手动录入 -> 确认/填写身份信息表单 -> 勾选用户协议 -> 提交认证 -> 等待审核 -> 认证成功。
- **异常流程**：认证失败 -> 进入失败结果页 -> 点击 Retry 重新发起认证流程。

## 3. 业务规则
### 3.1 输入规则
| 规则项 | 规则内容 | 说明 |
|--------|----------|------|
| 录入方式 | OCR识别 / 手动填写 | 支持上传图片自动识别或手动输入 |
| 证件类型 | Passport / Driver's License / National ID | 仅支持这三种证件 |
| 文件格式 | JPG/JPEG/PNG/PDF | 必须为可识别的证件图片 |
| 文件大小 | < 10MB | 超过限制提示错误 |

### 3.2 校验规则
| 字段 | 类型 | 必填 | 格式 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| Document Type | 单选 | 是 | - | - | 证件类型 |
| Document Number | String | 是 | 无特殊字符 | - | 证件号码 |
| Issuing Country | 下拉 | 是 | - | - | 签发国家 |
| Date of Birth | Date | 是 | 历史日期 | - | 出生日期 |
| First Name | String | 是 | 纯字母 | - | 名字 |
| Last Name | String | 是 | 纯字母 | - | 姓氏 |
| Email | String | 是 | 邮箱格式 | 登录邮箱 | 邮箱地址 |

### 3.3 权限规则
| 规则项 | 规则内容 | 说明 |
|--------|----------|------|
| 访问权限 | 仅限已登录用户 | 未登录重定向至登录页 |
| 认证次数 | 仅限一次 | 一个账号只能成功认证一次 |

### 3.4 业务约束
| 规则项 | 规则内容 | 说明 |
|--------|----------|------|
| 协议勾选 | 必须勾选 | 提交前必须同意用户协议和隐私政策 |
| 状态互斥 | 认证中(Verifying)不可提交 | 需等待审核结果 |

## 4. 错误处理
| 错误码 | 错误信息 | 触发条件 | 用户提示 |
|--------|----------|----------|----------|
| - | 必填为空 | 未填写必填字段点击Submit | "Cannot be empty"（字段边框变红高亮） |
| - | 格式错误 | 字段格式不合法 | "Invalid format" |
| - | 协议未勾选 | 未勾选用户协议点击Submit | 提示必须接受协议 |
| - | 上传失败 | 文件格式不支持或无法识别 | 提示上传有效证件 |
| - | 认证失败 | 审核未通过 | "Verification failed. We will contact you shortly with reasons" |

## 5. 依赖模块
- **上游依赖（谁调用我）**：
  - 钱包业务域：提现前检查 KYC 状态，未认证则引导至 KYC 页面。
  - 核心交易域：买家付款前或卖家发布高优商品前，可能触发 KYC 检查。
- **下游依赖（我调用谁）**：
  - OCR 识别服务：用于自动提取上传证件的文本信息。
- **跨域交互说明**：
  - KYC 认证结果（成功/失败）会同步给钱包系统和交易系统，作为解锁提现和收款功能的开关。

## 6. 已知问题
- **产品待确认问题**：
  - "User Agreement" 和 "Privacy Policy" 文本目前为纯文本 `<span>`，无 `href` 链接，点击无跳转。
  - 认证失败页的 "support@ok.com" 为纯文本，无 `mailto` 链接。
- **技术风险**：
  - OCR 识别准确率受图片质量影响，需确保手动修改链路（Enter Manually）的畅通。
