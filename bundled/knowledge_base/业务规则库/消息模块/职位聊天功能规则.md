# 消息模块 - 职位聊天功能规则

## 1. 功能概述
- **功能描述**: 用户在职位详情页点击 Contact 按钮后，进入与发帖者的一对一聊天页面，系统自动发送初始消息，发帖方可通过 AI Auto Reply 自动回复
- **用户角色**: 
  - 求职者/买家（Buyer）：发起聊天、发送消息
  - 发帖者/卖家（Seller）：接收消息、AI 自动回复
- **入口位置**: 
  - 入口1：职位详情页 → Contact 按钮
  - 入口2：职位详情页右侧悬浮卡片 → Contact 按钮
  - 入口3：直接访问聊天页面 `https://aepub.58v5.cn/biz/en/chat`
- **依赖模块**: 用户登录模块、AI Auto Reply 服务、职位详情模块

## 2. 核心流程
### 2.1 主流程
1. 用户在职位详情页点击 Contact 按钮
2. 系统检查登录状态：
   - 已登录：直接跳转聊天页面
   - 未登录：弹出登录弹窗或跳转登录页
3. 跳转到聊天页面 `aepub.58v5.cn/biz/en/chat`，URL 包含职位参数（postId、shopId、postName）
4. 系统自动发送初始消息："I'm interested in your job posting and open to discussing more details."
5. 用户在输入框输入消息，按 Enter 键发送
6. 消息显示在右侧（己方），输入框清空
7. AI Auto Reply 在 1-5 秒内自动回复，消息显示在左侧（对方）

### 2.2 异常流程
- 未登录点击 Contact → 触发登录流程，登录成功后跳回聊天页
- 输入框为空时按 Enter → 消息不发送，Send 按钮保持禁用
- 网络断开时发送消息 → 发送失败，显示错误提示
- 快速连续发送多条消息 → 每条消息独立发送（或防重提交，取决于产品设计）

## 3. 业务规则
### 3.1 进入聊天规则
| 功能 | 规则 | 说明 |
|-----|------|------|
| Contact 按钮跳转 | 点击后跳转至 `aepub.58v5.cn/biz/en/chat` | URL 包含 postId、shopId、postName 等参数 |
| 登录校验 | 已登录直接进入，未登录弹出登录弹窗 | 登录成功后自动跳回原聊天页 |
| 右侧边栏 Contact | 右侧悬浮卡片中的 Contact 按钮效果一致 | 与主区 Contact 功能相同 |
| 系统初始消息 | 首次发起聊天自动发送初始消息 | "I'm interested in your job posting and open to discussing more details." |
| 重复进入 | 再次点击 Contact 进入历史聊天记录 | 不重复发送初始消息 |

### 3.2 发送消息规则
| 功能 | 规则 | 说明 |
|-----|------|------|
| Enter 键发送 | 输入框中按 Enter 键发送消息 | 消息出现在右侧，输入框清空 |
| Send 按钮发送 | 点击 Send 按钮发送消息 | 与 Enter 键效果一致 |
| Send 按钮状态 | 输入框为空时 Send 按钮为 disabled 状态 | 输入内容后变为可点击状态 |
| 输入框清空 | 发送后输入框内容自动清空 | 回到空状态，显示 Placeholder |
| 消息显示位置 | 己方消息显示在右侧 | 包含发送时间戳 |
| 空格消息 | 仅输入空格时发送被阻止 | Send 按钮保持 disabled 或消息不显示 |
| Shift+Enter | 不发送消息，输入框内新增换行 | 或与 Enter 行为一致（待实测） |

### 3.3 接收消息规则
| 功能 | 规则 | 说明 |
|-----|------|------|
| AI Auto Reply | 发送消息后 1-5 秒内收到 AI 回复 | 消息显示在左侧，标注 "AI Auto Reply" |
| 对方消息位置 | 对方消息显示在左侧 | 包含头像、发送时间 |
| 消息时间戳 | 每条消息显示发送时间 | 格式待实测确认 |

### 3.4 聊天页面 UI 规则
| 元素 | 规则 | 说明 |
|-----|------|------|
| 对方信息显示 | 顶部显示对方名称（如 "OKer_wangyongli"） | 显示 "WhatsApp Reply" 标签 |
| 职位信息卡片 | 显示职位名称、地区、薪资、发帖时间 | 卡片可点击跳转回职位详情页 |
| 安全提示语 | 常驻显示："For your safety, please avoid sharing sensitive personal information such as bank details or passwords." | 位于聊天区域固定位置 |
| 输入框 Placeholder | "Input message" | 点击后获得焦点，Placeholder 消失 |

### 3.5 权限规则
| 角色 | 权限 | 说明 |
|-----|------|------|
| 未登录 | 无权限直接进入聊天 | 触发登录流程 |
| 已登录用户 | 可发起聊天、发送消息 | 正常使用所有聊天功能 |

### 3.6 边界规则
| 场景 | 规则 | 说明 |
|-----|------|------|
| 超长文字消息 | 发送成功，消息气泡完整显示（可能折行） | 或输入被限制到最大字数（待实测） |
| 特殊字符/Emoji | 正确显示，不被转义或截断 | 如："Hello! 😊 <test> & 'quote'" |
| 快速连续发送 | 每次 Enter 发送一条独立消息 | 或仅发送一条（防重提交，待实测） |
| 网络断开 | 发送失败，显示错误提示 | 如 "Failed to send" 或网络异常提示 |

| 错误码 | 说明 | 触发条件 |

## 6. 已知问题
### 6.1 产品待确认问题
- 测试用例中多数预期结果标注「⚠️ 推断」，需实际探测后补充：
  - Send 按钮点击发送的实际效果
  - Shift+Enter 是否支持换行
  - 空格消息的具体处理方式
  - 超长文字消息的字数限制
  - 快速连续发送的防重提交机制
  - 未登录时的具体跳转逻辑（弹窗 vs 跳转页面）
  - 消息历史记录是否持久化，刷新后是否保留

### 6.2 技术风险
- AI Auto Reply 响应时间依赖外部服务，可能存在延迟或失败
- 网络异常时消息发送失败的处理机制需验证
- 聊天记录持久化策略（本地存储 vs 服务端存储）
- 左侧消息列表的会话管理与排序逻辑
