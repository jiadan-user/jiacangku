# 招聘模块 - B 端职位发布（PC Web）业务规则

> **知识库依据**：由文本用例 [ok-sg-BizJobPublish-测试用例-20260414.md](../../文本用例/zhaopin/ok-sg-BizJobPublish-测试用例-20260414.md) 归档提取；站点与字段以线上为准。

## 1. 功能概述

- **业务价值**：招聘方在 PC Web（Biz 发布前台）完成雇主建档与多步骤职位发布，向 C 端 Jobs 供给职位。
- **用户角色**：已登录 B 端账号（Recruiter）；未登录先走登录，成功后需保留 `fromUrl` 等回跳路径。
- **入口位置**（示例，以各站 `pub` 域为准）：
  - 发布入口：`/biz/{lang}/publish/front`（及带 `categoryId` 的职位发布 URL）
  - 雇主信息（个人信息 + 公司）：`/biz/{lang}/zpInfo/profile?fromUrl=...`
  - 职位发布 Step1（Job Basic / Requirement 同页或同步）：`/biz/{lang}/publish/job?categoryId=...`
  - Job Detail：`/biz/{lang}/publish/job` 流程第二步（文案为 Post）

## 2. 核心流程

### 2.1 主流程

1. B 端登录 → 点击「发布职位」等入口。
2. **首次**：跳转雇主信息页 → 填写 Recruiter Information（头像规则、姓名、Email、站点相关 WhatsApp）与 Company Information → Confirm。
3. 进入 Job Basic：Job title、Job function、Workplace type、Location、Job type、Salary range 等 → Continue。
4. 同页或同步展示 Requirement：Experience、Education → Continue。
5. Job Detail：职位描述等 → **Post**（最后一步按钮由 Continue 变为 Post）。
6. 发布成功 → 成功页或职位管理/列表（以产品为准）。

### 2.2 异常与分支流程

- **未完成首次雇主信息**：中途关闭或未提交，再次点发布仍进入雇主信息页。
- **已完成首次**：再次点发布或刷新后再点发布，**不再**弹出雇主信息页，直接进入 Job Basic。
- **未登录**：先登录，回跳需保留目标路径（含 `fromUrl`）。
- **校验失败**：表单项 inline / HTML5 提示；断网时 toast/inline 网络错误，已填字段不丢失（见健壮性用例）。

## 3. 业务规则

### 3.1 输入规则

#### 3.1.1 个人信息 - 文字头像

| 规则项 | 说明 |
|--------|------|
| 生成来源 | 基于 **Last Name** 首字符生成文字头像（无上传入口） |
| 大小写 | 小写姓氏首字符展示为**大写** |
| 背景色 | 与账号 uid 规则绑定，同一账号多次拉取样式**一致**（不随机） |
| 落库 | `head_pic_url` 非空，HTTP 200，`Content-Type` 为 `image/*` |

#### 3.1.2 个人信息 - Email

| 规则项 | 说明 |
|--------|------|
| UMC 已有邮箱 | 进入页自动回填，可编辑 |
| UMC 无邮箱 | 字段为空且**必填**；格式非法不可提交 |
| 修改邮箱 | Edit Your Email 弹窗：发验证码 → 输入后 Confirm 高亮；确认后关闭并回显新邮箱；叉号关闭不保存 |

#### 3.1.3 个人信息 - WhatsApp（站点/配置相关）

| 规则项 | 说明 |
|--------|------|
| 可见性 | **BR/MX** 等配置站展示模块；**非 BR/MX**（如 SG）隐藏且版式**上移无空白** |
| 勾选框 | 输入框**空**时勾选框不可点；有合法号码后可点；部分国家配置**默认勾选**，部分配置**默认不勾选**（如 ES 场景用例） |
| 必填性 | WhatsApp 可为**非必填**（未填可提交，以 ES 等用例为准） |
| 文案 | 主/副文案完整（英/葡等 i18n 见多语言用例） |

#### 3.1.4 公司信息

| 字段/能力 | 规则 |
|-----------|------|
| 公司全称搜索 | 必填；联想选已有公司回填**法定全称**；可选 `+关键字` 创建新公司 |
| Logo | 创建/选中公司后出现上传区；格式 **PNG/JPG/SVG**；需支持真实选文件后预览与保存 |
| 再次编辑 | 可更换绑定公司实体并 Confirm；回显以最近一次保存为准（若业务禁止需单独产品规则） |

#### 3.1.5 Job Basic（页面 1）

| 字段 | 默认值/规则 |
|------|-------------|
| Workplace type | 默认 **Onsite**；可选 Onsite / Hybrid / Remote（单选） |
| Job type | 默认 **Full-time**；含 Part-time / Contract / Internship / Temporary 等（单选，以页面为准） |
| Job title | **必填** |
| Salary range | 用例约定：与 title、function、location、type 等一并填写时，**不填则无法下一步**（红色提示） |

#### 3.1.6 Requirement（页面 1 区域）

| 字段 | 默认值/规则 |
|------|-------------|
| Experience | 默认 **All levels**；枚举含 All levels、&lt;1 year、1–2 years、3–5 years、6–10 years、10+ years（展示文案以各语言 PRD 为准） |
| Education | 默认 **All levels**；8 档学历枚举（见用例） |
| 必填 | Experience、Education 不可清空后下一步（需校验提示） |

#### 3.1.7 Job Detail（页面 2）

| 规则项 | 说明 |
|--------|------|
| 加载 | 页面完整加载，无白屏 |
| 主按钮 | 底部主按钮为 **Post**（非 Continue） |
| 发布 | 填写描述后 Post → 成功跳转（成功页或管理页） |

### 3.2 校验规则

- **HTML5 必填**：First name、Last name、公司搜索等未满足时浏览器/页面提示（如 `Please fill out this field.`）。
- **Email**：无效格式不可进入发布页。
- **WhatsApp 号码**：用例期望无效格式拦截；**实测记录**（TC019）：BR 站无效长号码仍可能进入发布页，已登记缺陷，回归以最新线上为准。
- **姓名长度**：`maxlength=80`，超长输入被截断，边界 80 字符可成功提交。

### 3.3 权限规则

- 发布链路需 **B 端登录态**。
- 从发布入口进雇主信息需带 `fromUrl`，提交成功后回到对应 `categoryId` 发布步骤。

### 3.4 业务约束

- **多站点**：默认文档以 SG 为基线；BR/MX/ES/AE/US/HK/pt 等差异（WhatsApp、语言、RTL）按用例分站点执行。
- **PC 简化流程**：与移动端草稿能力不一致时，**勿按移动端标准验收 PC**（见原文档说明类备注）。

## 4. 错误处理

### 4.1 前端与网络

- 断网提交：预期出现网络错误提示，**不崩溃**，表单已填内容保留。
- 重复点击 Confirm/提交：预期单次提交、loading 防重复。

### 4.2 错误提示文案

- 表单项下方红色提示 / 浏览器原生提示；具体英文/多语言文案以 i18n 用例与 `pt.json` 等映射为准。

## 5. 依赖模块

| 类型 | 依赖说明 |
|------|----------|
| 上游（谁支撑我） | **用户/UMC**：邮箱是否存在、验证码发送；**账号体系**：B 端登录态 |
| 下游（我产出什么） | **Jobs 列表/详情**：新职位数据；**搜索/推荐**：可检索职位 |
| 跨域/通用 | **i18n**：多语言与 AE RTL；**存储/CDN**：头像与公司 Logo 资源 URL |

## 6. 已知问题

| 编号/来源 | 描述 |
|-----------|------|
| TC019 实测 | BR 站无效 WhatsApp 号码仍可能通过雇主信息提交，与期望「提交失败」不一致；需产品/研发确认是否补前端校验。 |
| TC051 | 英站发布流程部分字段已验，Job Description 需进入 Job Details 再验（文档内已标注进度）。 |
| SG 公司信息 | 当前 SG 实测无独立 Display Name 输入框；若他站有差异需按环境拆分用例。 |
