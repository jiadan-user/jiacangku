## Application Overview（阶段一摘要）

**功能定位**：车辆发布页面允许已登录用户发布二手车或新车信息，支持填写车辆基本信息、上传照片、设置价格和联系方式。

**用户角色**：已登录卖家（可发布、编辑、撤回车辆信息）、访客（无法访问发布页面）。

**业务规则（从 UI 推断）**：
- 车型、价格、外观照片、里程数、车身颜色、规格、联系电话、位置为必填字段 ✅ 实测
- 价格必须大于0，最大值为100,000,000 AED ✅ 实测
- 里程数不能为负数，最大值为99,999,999 km ✅ 实测
- 外观照片至少上传1张，最多9张 ✅ 实测
- 内饰照片可选，最多9张 ✅ 实测
- Description 可选，最大10000字符 ✅ 实测
- First Registration 可选，提供月份和年份选择 ✅ 实测

**页面状态枚举**：新建发布态、编辑发布态、车型选择对话框态、图片查看器态、撤回确认对话框态。

**模块划分（探测顺序）**：
1. [P0] 进入发布页面
2. [P0] 车型选择（三级联动）
3. [P0] 价格设置
4. [P0] 外观照片上传
5. [P1] 描述输入
6. [P0] 车辆信息（里程数、车身颜色、首次注册、规格）
7. [P1] 内饰照片上传
8. [P1] 联系信息（电话、位置）
9. [P0] 表单提交与验证
10. [P1] 编辑与撤回

## 发现的问题和改进建议

### 1. UX 问题：Location 搜索建议选择
- **问题**：在 Location 输入框中按 Enter 键会直接提交表单，而不是选择搜索建议
- **影响**：用户可能误触 Enter 键导致表单意外提交
- **建议**：修改键盘事件处理，Enter 键应该只选择搜索建议，不触发表单提交

### 2. 验证不一致：Contact Phone 字段
- **问题**：Contact Phone 字段标记为必填（*），但清空后仍可提交
- **影响**：可能导致用户混淆，不清楚该字段是否真的必填
- **建议**：
  * 如果该字段确实必填，应添加客户端验证
  * 如果该字段有默认值，应在 UI 上明确说明

### 3. 数据完整性：图片上传计数
- **观察**：上传1张外观照片后，计数器显示 "2/9"
- **推断**：系统可能自动生成了缩略图或多个版本
- **建议**：如果计数器表示文件数量，应与实际上传的文件数量一致；如果表示图片版本数量，应在 UI 上说明

### 4. 边界值提示缺失：价格和里程数
- **观察**：价格和里程数字段有最大值限制，但没有明确的 UI 提示
- **建议**：在字段旁边添加提示文本，说明有效范围（如 "Price: 1 - 100,000,000 AED"）
